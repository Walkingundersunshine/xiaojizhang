# 晓记账：无密钥汇率数据来源方案

| 项目 | 内容 |
| --- | --- |
| 决策编号 | T-025 |
| 调研日期 | 2026-07-30 |
| 当前状态 | 已选择方案 3：Frankfurter / 欧洲央行公开数据 |

## 1. 已确定要求

- 不要求用户申请或填写 API 密钥。
- 用户电脑直接联网获取汇率。
- 支持按日期获取历史汇率。
- 覆盖首版全部 12 种货币。
- 汇率只用于换算统计，不修改原始账目。

## 2. 方案 1：公开 JSON 汇率数据集（推荐）

使用开源项目 `fawazahmed0/exchange-api`，从 jsDelivr CDN 获取每日 JSON 文件；主地址失败时使用其 Cloudflare Pages 备用地址。

实测地址示例：

`https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@2026-07-29/v1/currencies/usd.json`

项目公开说明：

- 不需要 API 密钥。
- 每日更新并支持 `YYYY-MM-DD` 历史日期。
- 200 多种货币，实测包含全部 12 种目标货币。
- 声明无请求次数限制。
- GitHub 仓库许可证为 CC0-1.0。
- 提供 jsDelivr 与 Cloudflare 两个来源作为故障切换。

优势：无需注册、无项目服务器、结构化 JSON 比网页稳定、历史日期和货币覆盖满足要求。

劣势和风险：由第三方开源项目维护，不是央行官方数据；CDN 或项目可能停止更新；汇率是参考价格，不等于银行卡结算价。App 必须缓存数据、验证日期和数值，并在来源异常时停止换算而不是猜测。

官方仓库：[exchange-api](https://github.com/fawazahmed0/exchange-api)

## 3. 方案 2：直接抓取汇率网站 HTML 页面

选择一个展示历史汇率的网站，下载网页并解析页面中的表格或文本。

优势：符合“从网站页面获取”的直观理解；可能找到较丰富的图表和说明。

劣势和风险：页面改版就会失效；可能触发验证码、反爬或封锁；必须逐站审核服务条款和自动访问许可；HTML 中广告、地区格式和脚本会增加错误概率；自动测试困难。

不建议作为财务统计的主要数据源。

## 4. 方案 3：Frankfurter / 欧洲央行公开数据

使用无需密钥的 Frankfurter JSON 接口，其主要数据来自欧洲央行。

优势：免费、无需密钥、来源权威程度较高、接口稳定、支持历史日期。

劣势：当前只覆盖约 30 种货币，不包含 MOP 和 TWD，无法满足已经确定的 12 种货币完整换算。若选择该方案，MOP/TWD 只能保持原币统计，不能显示折算总额。

官方页面：[Frankfurter](https://frankfurter.dev/)

## 5. 我的建议

建议选择 **方案 1：公开 JSON 汇率数据集**。它满足“无 API 密钥、用户直接联网、历史汇率、12 种货币”四项要求，又避免脆弱的 HTML 抓取。

实现时将采用以下保护：

1. 先访问 jsDelivr，失败后访问 Cloudflare 备用地址。
2. 每个日期只下载并缓存一次 USD 基准数据。
3. 验证响应日期、货币代码、数值范围和 JSON 结构。
4. 周末或无数据日期向前查找最近一个可用日期，并明确显示实际汇率日期。
5. 两个来源都失败时只显示原币金额，不使用过期或猜测汇率。
