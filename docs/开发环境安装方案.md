## 1. 为什么现在需要决定

创建、检查和测试 Flutter 工程必须使用 Flutter SDK。当前电脑找不到 `flutter`、`dart` 和 `winget` 命令，因此不能通过系统软件商店自动安装，需要从 Flutter 官方发布地址获取 SDK。

Flutter Windows SDK 本身是压缩包，不是传统安装程序。所谓“安装”主要包括下载官方压缩包、解压到固定位置，以及决定是否修改 Windows 的 PATH 环境变量。

官方信息来源：

- [Flutter 手动安装说明](https://docs.flutter.dev/install/manual)
- [Flutter SDK 官方版本归档](https://docs.flutter.dev/install/archive)
- [Flutter 3.44.8 Windows 官方压缩包](https://storage.googleapis.com/flutter_infra_release/releases/stable/windows/flutter_windows_3.44.8-stable.zip)

## 2. 安装方案 1：项目内独立工具链

安装位置：`E:\jizhang\.tools\flutter`

做法：从官方地址下载稳定版 SDK，解压在项目的 `.tools` 目录中，不修改 Windows 全局或用户 PATH。项目命令始终使用这份 SDK。

优势：

- 只影响“晓记账”项目，不改变电脑上其他项目的 Flutter 版本。
- 版本清楚、容易固定，后续升级可以先验证再替换。
- 不需要写入项目目录以外的位置，也不需要修改环境变量。
- 如果安装出现问题，清理项目内工具目录即可，影响范围小。

劣势：

- SDK 和缓存会占用项目磁盘空间，可能达到数 GB。
- 其他 Flutter 项目不能直接复用这份工具链。
- 命令路径较长，需要通过项目脚本封装。

风险控制：

- `.tools/` 和 Flutter 缓存必须加入 `.gitignore`，不能提交到代码仓库。
- 官方压缩包下载后应保留版本和来源记录。

## 3. 安装方案 2：Windows 用户级工具链

建议位置：`C:\Users\Administrator\AppData\Local\Flutter\flutter`

做法：把官方 SDK 解压到当前 Windows 用户目录，并将 Flutter 的 `bin` 目录加入用户 PATH。

优势：

- 当前用户的所有 Flutter 项目都可以复用同一份 SDK 和缓存。
- 终端可以直接运行 `flutter` 和 `dart`，使用方便。
- 项目目录不会被大型 SDK 占用。

劣势：

- 会修改当前用户的 Windows 环境变量。
- 所有项目共享版本，一个项目升级 Flutter 可能影响其他项目。
- 写入用户目录和修改 PATH 需要额外系统授权。

风险控制：

- 修改 PATH 前记录原值，只增加明确的 Flutter `bin` 路径。
- 升级 SDK 前检查其他项目是否兼容。

## 4. 安装方案 3：通过 Git 获取稳定分支

建议位置：`C:\Users\Administrator\development\flutter`

做法：从 Flutter 官方 GitHub 仓库克隆 stable 分支，再由 Flutter 下载所需组件，并将 `bin` 加入用户 PATH。

优势：

- 可以通过 Git 明确查看版本和切换 Flutter 发布标签。
- 后续更新、比较版本和排查 SDK 源码比较方便。
- 所有 Flutter 项目可以共用。

劣势：

- 下载内容和 Git 历史通常更多，安装时间更长。
- 更依赖 GitHub 网络连接，在中国网络环境下可能不稳定。
- 同样会修改用户 PATH，并存在共享版本相互影响的问题。
- 对当前只是构建一个 App 的需求而言，管理复杂度偏高。

## 5. 对比

| 比较项 | 方案 1：项目内 | 方案 2：用户级 | 方案 3：Git 获取 |
| --- | --- | --- | --- |
| 对系统环境影响 | 最小 | 中等 | 中等 |
| 多项目复用 | 不复用 | 可复用 | 可复用 |
| 版本隔离 | 最好 | 一般 | 可切换但共享 |
| 安装复杂度 | 低 | 中 | 高 |
| 磁盘位置 | 项目磁盘 | 系统用户目录 | 系统用户目录 |
| 中国网络环境稳定性 | 取决于官方存储下载 | 取决于官方存储下载 | GitHub 可能更不稳定 |

## 6. 我的建议

建议选择 **安装方案 1：项目内独立工具链**。

原因：

1. 当前只开发“晓记账”，没有其他 Flutter 项目需要共享 SDK。
2. 它不会修改 Windows PATH，也不会影响电脑上的其他开发环境。
3. 可以把 Flutter 版本固定为 3.44.8，使项目构建更容易复现。
4. 当前项目目录位于 E 盘，通常比占用系统盘更合适。
5. 后续如果用户希望全局使用 Flutter，仍可迁移到方案 2，不影响 App 源码。

## 7. 选择后的操作

用户确认后，将执行：

1. 从 Flutter 官方发布地址下载 3.44.8 stable Windows SDK。
2. 解压到所选位置。
3. 验证 Flutter 和 Dart 版本。
4. 运行 `flutter doctor` 检查 Windows 桌面构建依赖。
5. 报告是否还缺少 Visual Studio C++ 桌面组件；若缺少，会另行说明安装体积和方案，得到用户决定后再安装。
6. 创建并验证“晓记账”Flutter 工程外壳。
