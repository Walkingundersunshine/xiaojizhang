## 不能直接使用中文的技术名称

Dart 包名、Windows 可执行文件名和 macOS Bundle Identifier 应使用 ASCII 字母。GitHub 仓库使用中文公开名称；源码中不能使用中文的技术标识统一采用拼音 `xiaojizhang`。

现有账本存放在操作系统按当前应用标识分配的数据目录中。直接更换所有标识会让新版本使用新的空目录，必须额外迁移旧数据库、日志和恢复前备份。

## 方案 1：显示名和可执行文件改名，保留内部数据标识（推荐）

- 界面、窗口标题、文档、Windows 产品信息和 macOS 显示名称全部改为“晓记账”。
- Windows EXE 改为 `xiaojizhang.exe`，内部测试包改为 `xiaojizhang-windows-...zip`。
- Dart 包名、Windows/macOS Bundle Identifier 和应用数据目录标识继续保留 `jizhangben`。

优势：用户看到的名称和文件名统一；旧账本、设置、日志和安全备份继续可用；不需要高风险的数据目录迁移。

劣势：源码 import、Bundle Identifier 和本机数据目录中仍能看到旧技术名 `jizhangben`；以后若一定要彻底更名，还需单独迁移。

## 方案 2：只修改用户可见名称

- 界面、窗口标题、文档和产品信息改为“晓记账”。
- EXE、Dart 包名、Bundle Identifier、数据目录和 ZIP 技术文件名继续使用 `jizhangben`。

优势：修改最少，数据兼容风险最低；构建脚本几乎不变。

劣势：用户下载和运行时仍会看到 `jizhangben.exe` 与旧 ZIP 文件名，品牌不完全统一。

## 方案 3：所有技术标识彻底更名

- Dart 包名改为 `xiaojizhang`，全部源码 import 同步修改。
- Windows EXE、macOS Bundle Identifier、应用数据目录、日志目录和测试包全部更换新标识。
- 首次启动新版本时迁移旧数据库、日志和恢复前备份。

优势：界面、源码、可执行文件、包标识和数据目录完全统一，不保留旧技术名。

劣势：改动范围最大；必须设计并测试一次性数据迁移、重复迁移、迁移失败回滚和两个系统的目录差异；macOS 无实机时无法完整验证；开源发布时间明显增加。

## 建议

建议选择方案 1。它让用户可见的程序和文件统一为“晓记账”，同时保留现有账本数据，是品牌一致性和数据安全之间最稳妥的选择。

## 实现与验证结果

- Flutter 窗口、导航品牌、Windows 文件属性和 macOS 显示名称均为“晓记账”。
- Windows 生成 `xiaojizhang.exe`；macOS 目标文件使用 `xiaojizhang.app`，Bundle Identifier 保留不变。
- Windows 明确继续使用旧的应用支持目录，只把旧目录名作为内部兼容常量保留。
- Release 实际启动时窗口标题、ProductName、FileDescription 和 OriginalFilename 验证通过。
- 启动后旧数据库仍存在且被使用，没有在“晓记账”新系统目录创建空数据库。
- 公开源码地址为 `https://github.com/Walkingundersunshine/xiaojizhang`。
