## 1. 要决定什么

决定同时存在人民币、美元、欧元等账目时，统计页面是否把不同货币换算为一个总金额。

## 2. 方案 1：不换算，按货币分别统计（推荐）

例如分别显示“人民币 ¥1,200.00、美元 $80.00”，不提供一个可能误导的跨币种总计。

优势：金额完全基于用户原始记录；无需联网、汇率服务或额外费用；隐私最好；结果容易核对。

劣势：无法一眼看到所有货币折算后的总支出；经常海外消费的用户需要自行估算。

成本：低。

## 3. 方案 2：用户手动设置汇率

用户选择本位币并手动填写各货币换算比例，统计页面同时显示原币和折算总额。

优势：无需联网；用户可以使用信用卡实际结算汇率；隐私风险低。

劣势：需要经常维护；不同日期使用同一汇率会导致历史统计不准确；输入错误会影响总计。

成本：中等。

## 4. 方案 3：联网自动获取历史汇率

App 连接第三方汇率服务，按花销日期获取汇率并自动换算。

优势：跨币种总计最方便；旅行和长期多货币使用体验最好；可按历史日期换算。

劣势：需要选择并依赖外部服务，可能产生订阅费用或调用限制；需要联网、缓存和服务故障处理；会暴露请求时间、币种等使用信息；汇率不一定等于银行卡实际结算价。

成本：高，长期还有服务维护成本。

## 5. 我的建议

建议首版选择 **方案 1：按货币分别统计**。它与“保存用户原始金额”的原则一致，不引入联网、隐私和持续费用。数据库会保留扩展空间，未来用户需要时再增加手动或自动汇率，不会修改原始账目金额。
