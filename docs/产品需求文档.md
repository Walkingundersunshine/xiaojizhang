## 1. 产品概述

“晓记账”是一款支持电脑和 Android 手机的跨平台应用，帮助用户快速、准确地记录日常花销，并使用清晰的二级分类了解钱花在了哪里。

首版以“把每笔花销记下来”为核心，不把预算、投资管理、复杂财务分析等功能混入最初版本，以保证操作简单、交付目标明确。

## 2. 产品目标

1. 用户可以在较少步骤内完成一笔花销记录。
2. 用户可以使用常用货币记录原始金额，不丢失货币信息。
3. 用户可以通过最多两级分类准确描述花销用途。
4. 用户可以查询、筛选、修改和删除历史记录。
5. Windows、macOS 与 Android 版本提供一致的核心记账体验，并针对电脑和手机分别适配操作布局。
6. 用户的本地数据应可靠保存，并提供可理解的数据备份或导出方式。

## 3. 目标用户与典型场景

### 3.1 目标用户

- 希望掌握个人日常支出的普通用户。
- 同时使用人民币、美元、欧元等多种货币的用户。
- 需要在 Windows 或 macOS 电脑上管理账目的用户。
- 不希望面对专业会计术语和复杂配置的用户。

### 3.2 典型使用场景

- 买完午餐后，记录金额、人民币、餐饮/午餐和备注。
- 海外旅行时，按当地货币记录交通、住宿和购物支出。
- 月末按时间、货币或分类筛选记录，了解支出构成。
- 发现记错金额后，找到原记录并修改。
- 更换电脑或重装系统前，导出或备份账本数据。

## 4. 首版功能范围

### 4.1 花销记录

每笔花销包含以下字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 金额 | 是 | 必须大于 0；显示和计算精度遵循所选货币 |
| 货币 | 是 | 使用标准货币代码保存，例如 CNY、USD、EUR |
| 一级分类 | 是 | 花销的大类 |
| 二级分类 | 是 | 一级分类下的具体用途；不允许第三级 |
| 发生时间 | 是 | 默认当前日期和时间，允许修改 |
| 备注 | 否 | 用户输入的简短说明 |
| 创建时间 | 系统生成 | 用于审计记录 |
| 更新时间 | 系统生成 | 用于判断最后修改时间 |

核心操作：

- 新增一笔花销。
- 查看花销列表。
- 查看单笔详情。
- 修改已有花销。
- 删除花销；删除前需要二次确认，降低误操作风险。
- 按日期范围、货币、一级分类和二级分类筛选。
- 按发生时间排序。

### 4.2 多货币

首版建议内置以下常用货币，并保留继续扩展的能力：

| 货币 | 代码 | 符号 |
| --- | --- | --- |
| 人民币 | CNY | ¥ |
| 美元 | USD | $ |
| 欧元 | EUR | € |
| 英镑 | GBP | £ |
| 日元 | JPY | ¥ |
| 港币 | HKD | HK$ |
| 澳门元 | MOP | MOP$ |
| 新台币 | TWD | NT$ |
| 新加坡元 | SGD | S$ |
| 澳大利亚元 | AUD | A$ |
| 加拿大元 | CAD | C$ |
| 韩元 | KRW | ₩ |

数据规则：

- 每笔花销始终保存用户输入的原始金额和货币代码。
- 不同货币不能在没有汇率的情况下直接相加。
- 首版始终保留按货币分别展示的原币汇总。
- CNY、USD、EUR 等 10 种货币可按交易日期的 Frankfurter/欧洲央行历史汇率折算为用户本位币；MOP、TWD 保持原币统计。

### 4.3 二级分类体系

分类结构严格限制为“一级分类 → 二级分类”，不提供第三级。

| 一级分类 | 二级分类 |
| --- | --- |
| 餐饮 | 早餐、午餐、晚餐、外卖、饮品、零食、聚餐、买菜 |
| 交通 | 公交地铁、出租网约车、火车、飞机、驾车用车、骑行、停车、过路费 |
| 居住 | 房租、房贷、物业、水费、电费、燃气、网络通信、维修、家居用品 |
| 购物 | 服饰鞋包、数码电器、日用品、美妆护理、家电、礼品、其他购物 |
| 娱乐 | 电影演出、游戏、音乐视频、运动健身、旅行度假、兴趣爱好、会员订阅 |
| 医疗健康 | 挂号诊疗、药品、体检、牙科、眼科、康复护理、健康用品 |
| 学习成长 | 书籍、课程、考试、培训、文具、软件工具 |
| 人情社交 | 请客、礼金、红包、礼物、聚会活动、公益捐赠 |
| 家庭与宠物 | 育儿、赡养、宠物食品、宠物医疗、宠物用品、家庭其他 |
| 金融支出 | 银行手续费、利息、保险、投资费用、其他金融费用 |
| 税费与政务 | 税款、证件办理、行政费用、其他税费 |
| 工作经营 | 办公用品、差旅、招待、物流、推广、专业服务、其他经营支出 |
| 其他 | 无法归类、临时支出 |

分类设计规则：

- 系统提供上述默认分类，减少首次使用的配置成本。
- 一笔花销只能选择一个一级分类和其下的一个二级分类。
- 一级分类与二级分类必须保持从属关系。
- 首版允许用户新增、重命名、停用和排序一级、二级分类，同时严格禁止第三级。
- 已被历史记录使用的分类不应直接物理删除；建议停用，以保证旧数据仍可理解。

### 4.4 查询与基础汇总

- 默认展示近期花销记录。
- 显示当前筛选范围内的笔数和金额汇总。
- 多货币记录按币种分别汇总。
- 可按一级分类和二级分类查看分类汇总。
- 暂不在没有明确汇率规则时显示跨币种总计。

### 4.5 数据管理

- 数据默认保存在用户自己的电脑上。
- App 退出或系统重启后，数据仍然存在。
- 提供导出功能；建议首版至少支持 CSV。
- 提供本地备份与恢复能力；具体文件格式需在技术方案确定后决定。
- 删除、恢复或覆盖数据前必须给出明确提示。

## 5. 页面与信息架构

### 5.1 首页 / 记录列表

- 展示近期花销和当前筛选条件下的汇总。
- 提供明显的“记一笔”入口。
- 提供日期、货币、分类筛选和排序。
- 点击记录进入详情或编辑。

### 5.2 新增 / 编辑花销

- 金额作为首要输入项。
- 货币默认使用用户最近一次选择或设置中的默认货币。
- 分类先选一级，再选二级。
- 发生时间默认为当前时间。
- 保存前检查金额、货币和分类是否合法。

### 5.3 统计

- 按所选时间范围展示分类支出。
- 多种货币分别展示，除非以后启用汇率折算。
- 支持从汇总结果查看对应明细。

### 5.4 设置

- 默认货币。
- 分类管理（若确认纳入首版）。
- 数据导出、备份和恢复。
- 版本信息。

### 5.5 局域网同步

- Android 底部导航直接提供“同步”入口；电脑端左侧导航提供相同入口。
- 电脑建立真实加密监听服务后显示短时二维码；未建立监听时不得显示无法连接的二维码。
- 二维码和备用手动短码统一有效 2 分钟；过期后由电脑重新生成。
- 局域网消息使用 HTTPS 请求；每次连接严格核对二维码或已配对设备保存的证书 SHA-256 指纹。
- Android 用户主动进入扫码页后调用相机，只识别晓记账自己的配对格式，不打开普通网址。
- 相机不可用、权限被拒绝或扫描失败时，提供连接地址和一次性短码的手动输入入口。
- 备用短码为 6 位数字，与二维码共用 2 分钟有效期；同一配对窗口累计失败 5 次后立即作废。
- 首次配对后的每次同步使用双向 TLS；手机固定电脑证书指纹，电脑只接受已配对手机证书。
- 首次配对后长期记住设备，用户可手动移除；同步始终需要用户主动发起。
- 对方公开证书、证书指纹与配对状态保存在 SQLite 独立设备表；本机身份私钥仍只保存在系统安全存储。
- 已配对设备不进入 CSV、`.jizhang` 完整备份或恢复；恢复账本不得改变本机设备信任。

## 6. 核心用户流程

### 6.1 记录一笔花销

1. 用户点击“记一笔”。
2. 输入金额并选择货币。
3. 选择一级分类和二级分类。
4. 需要时修改时间或填写备注。
5. 点击保存。
6. 系统校验成功后保存，并在列表中显示新记录。

### 6.2 查找并修改记录

1. 用户在列表中使用日期、货币或分类筛选。
2. 点击目标记录查看详情。
3. 进入编辑，修改内容并保存。
4. 系统更新记录并保留最后更新时间。

## 7. 非功能要求

### 7.1 平台兼容

- 支持仍处于主流支持周期内的 Windows 和 macOS 版本；最低系统版本在技术选型后明确。
- Android 支持 Android 10（API 29）及以上。
- Windows、macOS 和 Android 的核心数据结构和功能保持一致。
- 安装包应符合各平台的常见安装习惯。

### 7.2 易用性

- 高频的新增花销流程应尽量减少点击和输入。
- 金额、时间、货币和分类的错误提示应使用日常语言。
- 破坏性操作必须明确提示后果。

### 7.3 数据可靠性与隐私

- 金额不得使用可能产生常见小数误差的方式保存。
- 本地数据库写入失败时应明确告知用户，不能显示“保存成功”。
- App 不应在未经用户同意的情况下上传账目数据。
- 备份与恢复应避免静默覆盖现有数据。
- 账本备份和恢复不得复制、覆盖或重新启用已配对设备信任。

### 7.4 性能

- 常规启动、打开记录列表和保存记录应让用户感到流畅。
- 首版按至少 10 万笔本地记录仍可正常查询的目标进行设计，实际指标在技术方案确定后测试。

### 7.5 可维护性

- 数据结构需要支持后续增加收入、账户、预算和同步功能。
- Windows 和 macOS 尽量共用同一套业务代码，降低长期维护成本。

## 8. 首版验收标准

1. Windows 和 macOS 均能安装、启动和正常退出。
2. 用户能够新增包含金额、货币、两级分类、时间和备注的花销。
3. 重启 App 后，已保存的花销仍存在且数据一致。
4. 用户能够查看、筛选、修改和删除花销。
5. 分类选择只允许两级，不能出现错误的跨分类组合。
6. 同一筛选范围存在多种货币时，金额按货币分别汇总。
7. CSV 导出结果包含完整的核心字段，并能被常见表格软件打开。
8. 关键操作失败时显示清楚的错误信息，不造成静默数据丢失。

## 9. 暂不纳入首版的建议范围

以下内容并非永久排除，而是等待用户确认优先级：

- 收入记录与收支结余。
- 预算、超支提醒和账单提醒。
- 银行卡、现金、电子钱包等账户体系。
- 自动读取银行账单或票据识别。
- 互联网云同步和多人共享账本。
- 实时汇率与自动换算。
- iOS 手机端、网页端。
- 投资资产和负债管理。

## 11. 版本规划建议

### v0.1：可用原型

- 新增、查看、编辑和删除花销。
- 多货币原始金额记录。
- 默认二级分类。
- 本地数据保存。

### v1.0：首个正式版本

- 完整筛选与基础分类统计。
- CSV 导出、本地备份与恢复。
- Windows 和 macOS 安装包。
- 完成数据可靠性、性能和跨平台验收。

### 后续版本

- 根据用户决定逐步考虑自定义分类、收入、账户、预算、汇率、云同步和移动端。
