# 晓记账：汇率数值保存方案

| 项目 | 内容 |
| --- | --- |
| 决策编号 | T-026 |
| 日期 | 2026-07-30 |
| 当前状态 | 已选择并实现方案 1：固定 12 位精度整数 |

## 1. 要决定什么

决定从 Frankfurter 获取的多位小数汇率如何保存在 SQLite 中。该决定只影响汇率缓存和换算；用户原始金额仍按最小货币单位保存为整数。

## 2. 方案 1：固定 12 位精度整数（推荐）

把每个汇率乘以 `1,000,000,000,000` 后保存为 64 位整数。例如 `7.812345` 保存为 `7812345000000`。换算时使用 Dart 的大整数完成乘除，最后只在目标货币最小单位处四舍五入一次。

优势：数据库内没有二进制小数误差；统计结果稳定、可重复；无需增加十进制第三方库；12 位精度远高于来源实际精度。

劣势：代码需要统一的缩放和四舍五入函数；调试数据库时整数不如原始小数直观。

成本：低。

## 3. 方案 2：十进制文本

原样保存 `"7.812345"`，使用高精度十进制库解析和计算。

优势：数据库中容易阅读；可保留来源返回的小数形式；理论精度灵活。

劣势：需要额外依赖；SQLite 不能直接对文本汇率计算；缓存校验和统计代码更复杂。

成本：中等。

## 4. 方案 3：SQLite `REAL` 普通小数

直接以数据库浮点数保存汇率。

优势：代码最少；数据库可直接计算。

劣势：存在二进制小数误差；不同计算顺序可能产生极小差异；不符合项目对金额统计可重复性的目标。

成本：初期低，长期正确性风险较高。

## 5. 我的建议

建议选择 **方案 1：固定 12 位精度整数**。汇率本身是参考值，但换算过程仍应确定、可重复。使用固定精度整数可以与已经确定的整数金额方案保持一致，同时不增加第三方计算依赖。
