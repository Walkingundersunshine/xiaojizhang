## 要决定什么

晓记账 Android 版最低支持哪个 Android 系统版本。版本低于该要求的手机不能安装 APK。

## 方案 1：Android 7.0 及以上（API 24）

采用当前 Flutter 默认最低版本，尽量覆盖较老的 Android 手机。

优势：可安装设备范围最大；不额外提高 Flutter 的默认门槛。

劣势：Android 7 已非常老旧，许多设备没有系统安全更新；需要测试更多旧系统差异；文件选择、网络权限和系统界面的体验可能不一致。

成本和风险：开发测试成本最高；由于晓记账当前本地数据库不加密，在停止安全更新的旧手机上使用会增加数据隐私风险。

## 方案 2：Android 8.0 及以上（API 26，推荐）

排除最老的一批设备，同时仍支持较广泛的 Android 手机。

优势：兼容范围与维护成本较平衡；系统行为比 Android 7 更统一；仍能覆盖不少旧手机。

劣势：Android 7 手机无法安装；Android 8 本身也已经较旧，仍需要关注厂商定制系统差异。

成本和风险：测试成本居中；使用长期未更新的旧手机时，系统自身安全风险仍由用户承担。

## 方案 3：Android 10 及以上（API 29）

只支持相对较新的手机系统。

优势：系统权限、文件访问和安全机制更现代；需要兼容的旧行为更少；测试和长期维护较简单。

劣势：Android 9 及更早手机不能安装，可能排除仍在使用旧设备的用户。

成本和风险：开发测试成本最低，但用户覆盖范围最小。

## 我的建议

建议选择方案 2：Android 8.0 及以上。它在旧手机覆盖和开发维护之间较平衡。如果你明确希望尽可能多的老手机都能安装，可以选择方案 1；如果目标用户基本都使用较新手机，可以选择方案 3。

## 已确定的构建范围

- 最低版本：Android 10 / API 29；更旧手机不能安装。
- 目标版本：Android API 36，遵循当前 Flutter 和 Android 的新平台行为。
- 编译版本：Android API 36。
- 不因为最低版本选择而降低桌面端兼容性。
