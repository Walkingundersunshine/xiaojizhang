# 晓记账：分类管理范围方案

| 项目 | 内容 |
| --- | --- |
| 产品决策编号 | P-002 |
| 日期 | 2026-07-29 |
| 当前状态 | 已选择方案 2：完整分类管理 |

## 1. 要决定什么

决定首版用户能否修改系统提供的 13 个一级分类和 82 个二级分类。

## 2. 方案 1：首版只使用默认分类（推荐）

用户可以选择全部默认二级分类，但不能新增、改名、排序或停用。

优势：首版操作简单、开发快，所有分类统计口径一致，也不会发生误删历史分类。

劣势：个别用户找不到完全合适的分类时，只能使用“其他”。

## 3. 方案 2：提供完整分类管理

用户可以新增一级和二级分类、重命名、排序和停用；已使用的分类不允许物理删除。

优势：最灵活，可以完全适应个人习惯。

劣势：需要额外管理页面和复杂校验，用户误操作会影响历史统计理解，首版开发量明显增加。

## 4. 方案 3：固定一级分类，只允许管理二级分类

13 个一级分类固定；用户可以在其下新增、排序和停用二级分类，系统默认分类不能删除。

优势：比方案 1 灵活，同时保持一级统计口径稳定。

劣势：仍需分类管理界面；需要自定义一级分类的用户无法满足。

## 5. 我的建议

建议选择 **方案 1** 完成首个可用版本。当前默认分类已经覆盖常见花销，先验证新增、列表、筛选和统计是否好用。数据库已经预留 `isSystem`、`isActive` 和排序字段，以后升级到方案 2 或 3 不需要推翻现有账目结构。
