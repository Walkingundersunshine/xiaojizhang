# 晓记账：同步设备私钥保存方案

| 项目 | 内容 |
| --- | --- |
| 技术决策编号 | T-044 |
| 日期 | 2026-07-30 |
| 当前状态 | 已选择方案 1：使用各平台系统安全存储 |
| 说明 | 只保护设备身份私钥，不改变“账本数据库不加密”的既定决定 |

## 要决定什么

用于证明已配对设备身份的长期私钥保存在什么位置。私钥一旦被复制，其他程序可能冒充这台设备发起同步。

## 方案 1：使用 Windows/macOS/Android 系统安全存储（推荐）

通过 Flutter 的安全存储组件，让 Android 使用系统密钥保护能力，Windows 和 macOS 使用各自的系统凭据或钥匙串保护能力。App 只在需要建立加密连接时读取私钥。

优势：不把私钥明文放在 SQLite 或普通文件中；不要求用户每次输入密码；符合三个目标平台的常见安全做法；设备被移除后可以删除对应信任信息。

劣势：需要增加一个跨平台插件并分别测试；系统账户迁移、清除应用数据或重装可能使私钥丢失，之后需要重新配对；不同平台的备份行为不完全相同。

成本和风险：组件本身免费；开发和测试成本居中；必须禁止将安全存储内容导出到账本备份。

## 方案 2：私钥明文保存在 App 本地文件或 SQLite

把私钥与普通设置一起保存在应用数据目录。

优势：实现最简单；不增加系统安全存储组件；备份和调试较容易。

劣势：能读取应用数据目录的其他程序或恶意软件可以复制私钥并冒充设备；与长期记住设备的安全目标不匹配。

成本和风险：开发成本最低，但身份冒用风险最高，不建议采用。

## 方案 3：用户密码加密私钥

首次配对时让用户设置密码，使用密码派生密钥加密私钥；需要同步时输入密码解锁。

优势：即使私钥文件被复制，没有密码也较难使用；不完全依赖系统安全存储。

劣势：增加密码设置、输入、修改和忘记密码流程；忘记密码无法恢复，只能移除设备并重新配对；日常同步步骤明显增加。

成本和风险：开发和测试成本最高；密码强度不足会降低保护效果；不能提供会泄露私钥的找回机制。

## 我的建议

建议选择方案 1。它能在不要求用户管理新密码的情况下保护设备身份，并且只影响同步私钥，不会擅自加密现有账本数据库。

## 已确定的实现约束

- 使用跨平台安全存储组件，但分别验证 Android、Windows 和 macOS 的系统实现。
- 只保存同步身份私钥和必要的非账本身份信息，不把花销、分类、备注或完整备份写入安全存储。
- 私钥不进入 SQLite、`.jizhang`、CSV、日志、二维码或网络诊断信息。
- 清除应用数据、系统安全存储失效或重装导致私钥丢失时，提示用户重新配对，不尝试从账本备份恢复私钥。
- 已配对设备的公开身份、显示名称和最后同步时间可以保存在普通数据库；私钥必须单独保存在系统安全存储。
- 此决定不改变 T-006“账本数据库不加密”。
