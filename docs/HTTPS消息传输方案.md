## 要决定什么

在已经确定使用 TLS 加密连接后，配对请求、同步摘要和后续账本变更通过什么消息形式发送。

## 方案 1：HTTPS 请求（推荐）

使用 Flutter/Dart 自带的 HTTPS 服务端和客户端。手机对电脑的明确地址发出请求，服务端以状态码和 JSON 响应返回结果。

优势：HTTP 的消息边界、状态码和超时规则成熟；配对和分批同步都是清晰的一问一答；不增加第三方依赖、账号、云服务器或费用；问题容易定位。

劣势：需要持续进度时要由手机分次查询，或者以后增加单独的进度接口；不能像长连接一样由电脑随时主动推送消息。

成本和风险：开发成本最低；必须为每次自签名证书连接严格核对二维码或已配对设备保存的 SHA-256 指纹，不能全局忽略证书错误。

## 方案 2：加密 WebSocket

在 TLS 上建立长期双向连接，手机和电脑可以持续互发进度、冲突和完成事件。

优势：实时进度和双向事件自然；一次同步期间不用反复建立连接。

劣势：断线重连、应用切换、重复消息和连接状态更复杂；对当前用户主动、短时局域网同步偏重。

成本和风险：无服务费用，但开发和测试成本高于 HTTPS；断线处理错误可能造成重复提交。

## 方案 3：原始 TLS 字节流

直接在 TLS 连接中发送自定义消息，不使用 HTTP 或 WebSocket。

优势：依赖最少，协议可以完全按晓记账定制。

劣势：需要自行实现消息边界、长度限制、状态码、超时和错误恢复；调试与长期兼容最困难。

成本和风险：开发和安全审查成本最高；自定义协议解析错误可能造成内存占用或半条消息问题。

## 已完成的实现约束

- 使用 Dart 自带 `HttpServer.bindSecure` 和 `HttpClient`，不增加网络框架或云服务。
- 每次局域网请求创建独立客户端；允许自签名证书的回调只接受本次目标 IP、端口和指定 SHA-256 指纹，不能影响汇率等其他联网功能。
- 已建立版本化状态地址 `/xiaojizhang/v1/status`，未知地址返回 404，错误请求方式返回 405。
- 状态响应禁止缓存、限制最大长度，并校验固定协议名和版本。
- 服务端只能由调用方主动绑定指定地址；关闭后不再接受连接。
- 配对令牌、账本摘要和同步提交接口尚未实现，因此当前界面继续不显示可连接二维码。
- `flutter analyze` 无问题；58 项普通自动测试、Windows 系统安全存储真实集成测试、Android Debug APK 和 Windows Debug 构建均通过。
